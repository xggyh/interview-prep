📐 4 个必背公式

1. LLM 月成本

$/conv = (in_tok × $in + out_tok × $out) / 1,000,000 $/月 = $/conv × conv_per_day × 30
例: 客服 agent, 5K in + 500 out, Gemini Pro
$/conv = (5000×2 + 500×12) / 1M = $0.016
1M conv/月 → $16K/月

2. 向量库内存

RAM (GB) = N × dim × 4 (float32) / 1024³ PQ 压缩后 ≈ 上面 / 30
例: 5000 万 doc × 1024 dim
Float32: 200GB · PQ 压缩后: ~7GB · 单机 64GB instance 装得下 (留 headroom)

3. 并发 (Little's Law) — 算 DB pool / GPU batch

in_flight = QPS × latency (秒)
例: 1000 QPS × 0.2s p95 = 200 在 flight
DB pool size = 200 × 1.25 buffer = 250 connections

4. Storage 月成本

$/月 = GB × $0.023 (GCS standard) OR GB × $0.004 (GCS Glacier) + egress: GB out × $0.09 (AWS to internet) GB cross-region × $0.02

📦 P1 · 听到「几百万 / 上亿用户 / N 个文档」→ Storage + Memory

Trigger: 用户量 / 文档数 / 记录数 / 行数 / 历史 N 年数据

① 你必须先澄清的 3 件事

  1. 数据类型: 文本 / PDF / 图片 / 视频 (单位大小差 10-100x)
  2. 留存周期: 永久 vs 90 天 vs 7 年 (HIPAA / SOX 要求 7+ 年)
  3. 索引粒度: 整 doc 还是 chunk? chunk 数 = doc × 10-50, embedding 占大头

② 估算公式

Total Storage = N × avg_size × replication × growth Memory (向量库) = N × dim × 4 bytes / 30 (PQ 压缩后)

③ 必背 anchor 数字

单位大小
1 个 PDF 病历50-200KB (含 OCR text)
1 个 text chunk (512 tok)~2KB
1 个 embedding (1024 dim float32)4KB
1 个 embedding (PQ 压缩后)96-128B
1 个 chunk 进 vector store~6KB (text + embed + metadata)

④ 完整 worked example (Gao Xin 项目)

5000 万医疗文档 HIPAA RAG (Q21)
Step 1 — Chunk 计算: 5000万 × 10 chunk/doc = 5 亿 chunks
Step 2 — Storage 拆分:
  • Text (raw): 5亿 × 2KB = 1TB (GCS = $23/月)
  • Embedding float32: 5亿 × 4KB = 2TB (GCS = $46/月)
  • Embedding PQ 压缩: 5亿 × 100B = 50GB (in-memory)
  • Vertex AI Vector Search index 含 metadata: ~3-4TB
Step 3 — Memory 实际能装: PQ 后 50GB → 单 64GB r6g.4xlarge 装下, 但生产留 3 节点 (HA + 增长)
Step 4 — 月成本: Vertex AI Vector Search m5.4xlarge × 3 = $3K/月 + GCS + cross-region replication ≈ $5K-10K/月 储存

⑤ 常见坑

Trap 1: 只算 raw byte, 忘了 metadata / index / WAL 倍数 (实际 ×1.5-2)
Trap 2: 忘 replication factor (GCS 默认 3 副本已含, 但 DB / ES 是额外的)
Trap 3: 算了 storage 不算 memory (vector search 是 RAM-bound)
Trap 4: 假设 chunk 数 = doc 数 (实际 10-50x)

⏱️ P2 · 听到「实时 / 低延迟 / sub-100ms」→ Latency Budget per Hop

Trigger: 实时 / 秒级 / sub-100ms / 低延迟 / interactive / real-time

① 澄清 3 件事

  1. p50 vs p99? "100ms" 默认是 p50, p99 通常 ×3-5 (i.e., p99=300-500ms)
  2. 端到端 vs 服务端 only? 端到端含网络 RTT, 服务端 only 是 server work
  3. 网络 RTT? 同 region 1-2ms, 跨 region 50-100ms — 这是 fixed cost 必须先扣

② 估算流程 (5 步)

1. 写下目标: p99 = X ms (e.g., 100ms) 2. 减 fixed cost: - Client→LB: 5-20ms (depends on CDN/edge) - LB→backend: 1-2ms - Return: 5-20ms ⇒ 业务可用 = X - 20-40ms 3. 按 0.1/1/10/100ms 分桶, 每跳给 budget 4. 加 cache: hit rate × cache_latency + miss × full_path 5. p99 = (p99 of each step) sum, 不是 avg 相加

③ 必背的 budget 模板

目标 p99能做啥不能做啥
10mscache lookup, in-memory hash任何外部 call
100mscache + 1 DB call + 1 简单 logicLLM, vector search 大库, 跨 region
500ms+ LLM Flash 短答 + RAG 简单Gemini Pro 长文, 复杂 agent
2s+ LLM Pro + 完整 RAG2M context, multi-step agent
10s++ 2M context, agent 5+ tool call实时交互 (用户跑掉)

④ Worked example

客户要 sub-100ms LLM 搜索 (Q28)
目标: p99 100ms 端到端
Budget 拆解:
  • Client → server network: 20ms
  • 业务可用: 80ms
  • LLM call (Flash, 短答) 200ms+ ❌ 装不下!
结论: 100ms 不能有 LLM 在 critical path
方案:
  • 60% 走 cache (Redis, 5ms): 60% × 5 = 3ms
  • 30% 走 Flash 短答 (200ms): 但用户感知用 streaming first-token
  • 10% 走 Pro 完整 RAG (1s): 用户接受偶尔慢
  • Avg perceived first-token: 60×5 + 40×100 = ~43ms ✓

⑤ 常见坑

Trap 1: 心里只想 p50, 说 "100ms" 实际是 p50, 客户要 p99 立刻翻车
Trap 2: 算了服务端忘了网络 (跨 region +50-100ms 是死局)
Trap 3: Cascade 服务忘累加 (A → B → C, 每个 50ms = 150ms 不是 50ms)
Trap 4: 算 happy path 忘 retry / timeout (失败 case latency ×2-3)

💰 P3 · 听到「LLM / RAG / 模型」→ $/conv × volume = $/月

Trigger: LLM / RAG / agent / GPT / Claude / Gemini / chatbot / assistant

① 澄清 3 件事

  1. Input 长度: context size 大概多少 token? (FAQ: 500 / RAG: 5K / Long doc: 200K)
  2. Output 长度: 短答 (100) / 长生成 (5K)? 输出贵 6x
  3. Volume: 每天多少 conv / query?

② 估算公式

$/conv = (in_tok × $in + out_tok × $out) / 1M $/月 = $/conv × conv/天 × 30 省钱: × (1 - cache_hit_rate × 0.5) # auto cache 50% off × 0.5 if batch_api × 0.25 if Flash 替 Pro × 0.1-0.2 if self-host (但要 break-even)

④ Worked example

TikTok PayLater 客服 agent, 1M conv/月
Step 1: 单 conv = RAG, 5K in + 500 out
Step 2: Gemini Pro list price = $0.016/conv → $16K/月
Step 3: 加 60% cache hit (热门 FAQ 重复): $16K × (1 - 0.6×0.5) = $11.2K/月
Step 4: 改 Gemini Flash (90% task ok): $11.2K × 0.25 = $2.8K/月 ← 省 83%

⑤ 常见坑

Trap 1: 只算 input 忘 output (output 6x 贵, 输出 token 才是 cost 大头)
Trap 2: 用 list price 不算 cache / batch (生产应该 30-60% cache hit)
Trap 3: 忘 Embedding cost (RAG ingest 时一次性, 但 5亿 chunk × $0.02/1M = ~$1K-5K, 不小)
Trap 4: 忘 retry tokens (failed call 还是消耗 token, 4-5% overhead)

🖥️ P4 · 听到「自托管 / on-prem」→ GPU 数 + Utilization Break-even

Trigger: self-host / 自托管 / on-prem / 不出 VPC / private / Llama / Mixtral / open weight

① 澄清 3 件事

  1. 实际 token/s 需求: peak / avg ratio? 业务 8h vs 24/7?
  2. Latency 要求: < 200ms 必须 self-host, > 500ms hosted 也行
  3. 数据 sensitivity: 如果 hosted 走 BAA + zero retention 能签, 别自托管 (烧钱)

② 估算公式

Throughput needed = QPS_peak × avg_output_tok (tok/s) GPU count = ceil(throughput / per_GPU_throughput / utilization) Break-even vs hosted: self-host $/月 = GPU_count × $/hr × 24 × 30 + ops_FTE × $20K/月 hosted $/月 = $/conv × volume 找交叉点 经验: < 100M tok/月 → hosted always win 100M-1B tok/月 → hosted 通常 win (除非 latency/data) > 1B tok/月 → self-host win 5-10x (24/7 满载) Utilization < 50% → self-host 永远输

③ 必背 anchor

项数字
H100 on AWS (on-demand)~$5/hr
H100 on AWS (1-year reserved)~$3/hr (-40%)
A100 80GB (on-demand)~$3/hr
Llama 3 8B on H100 decode5-10K tok/s
Llama 3 70B on 2×H100 decode1-2K tok/s
Utilization target (production)60-70% (留 headroom)
Ops FTE 全负载$200-300K/年

④ Worked example

F500 客户问: 1M conv/月 是否自托管 Llama 3 70B?
Step 1 — Throughput: 1M conv × 500 out tok = 500M tok/月. Peak 5x avg → ~2K tok/s peak
Step 2 — GPU 数: 70B on 2×H100 = ~2K tok/s. 1 instance (2 H100) 撑住 peak, 但单点风险 → 2 instances HA
Step 3 — Self-host cost: 4 × H100 × $5/hr × 24 × 30 = $14.4K/月 + ops 0.5 FTE = $10K/月 = $24K/月
Step 4 — Hosted cost (对比): 5K in + 500 out × $0.50/$3 (Flash) = $0.004/conv × 1M = $4K/月
结论: Hosted 便宜 6x ✓
啥时候反过来: 量增到 10M conv/月 = 5B tok/月, self-host $24K, hosted $40K — self-host 才赢. 量不到不要自托管.

⑤ 常见坑

Trap 1: 算单 GPU 单价没算 ops 成本 (实际 ops 2-3 FTE = $300-600K/年, 把 break-even 推远)
Trap 2: 假设 24/7 满载 (实际业务 8h, utilization 33%, self-host idle 烧 2/3 钱)
Trap 3: 忘 capacity buffer (peak 是 avg × 5-10x, 必须留 headroom)
Trap 4: 用 list GPU 价没算 reserved instance (1y reserved -40%, 3y -60%)

🌍 P5 · 听到「多 region / F500 / SLA」→ Availability + Egress + DR Cost

Trigger: F500 / 多 region / 99.99 / SLA / DR / global / multi-AZ / disaster recovery

① 澄清 3 件事

  1. SLA 几个 9? 99.9 vs 99.99 vs 99.999 down time 差 10-100x
  2. RTO / RPO 多少? RTO = 恢复时间, RPO = 数据丢失时间; F500 一般 RTO 5min RPO 0
  3. 全球分布: 几个 region? cross-region egress 是 silent killer

② 估算公式

Downtime 预算 (年): 99.9 (3 nine) : 8.76 小时 99.95 (3.5) : 4.38 小时 99.99 (4 nine) : 52.6 分钟 99.999 (5) : 5.26 分钟 Multi-region 成本倍数: Active-active 2 region: 2x infra Active-passive: 1.5x (passive 半负载) Cold DR standby: 1.2x Egress cost: AWS cross-region: $0.02/GB AWS to internet: $0.09/GB LLM output 1 tok ≈ 4-8 bytes (含 JSON overhead)

③ 必背 anchor

SLAAnnual DowntimeMonthly典型方案
99.03.65 天7.3 小时单 instance 也行
99.98.76 小时43.8 分钟多 AZ 单 region
99.954.38 小时21.9 分钟多 AZ + auto-failover
99.9952.6 分钟4.4 分钟active-active 2 region

④ Worked example

F500 客户要 99.99% SLA, 多 region (Q23)
Step 1 — Downtime budget: 99.99 = 52 min/年 ≈ 4 min/月. 任何 deploy / DR drill 都要算进去
Step 2 — Single region 不够: AWS RDS SLA 是 99.95 (4h/年), 单 region 不达标
Step 3 — 方案: Active-Active 2 region
  • us-east-1 主, us-west-2 主 (Route53 weighted)
  • Aurora global database, cross-region replication
  • Health check + auto-failover (2 min RTO)
Step 4 — Cost breakdown:
  • Infra: $50K/月 × 2 = $100K
  • Cross-region replication egress: 假设 50GB/天 × 30 = 1.5TB/月 × $0.02 = $30 (可忽略)
  • Egress to internet (用户请求): 假设 10TB/月 × $0.09 = $900
  • 24/7 on-call: 2 FTE × $20K = $40K
  • Monitoring (Datadog): $5K
  Total: ~$145K/月 (vs single region ~$70K, 增量 +$75K for 99.99)

⑤ 常见坑

Trap 1: 99.9 vs 99.99 看起来差不多, 实际差 10x — 客户不知道, 你说服他降到 99.95 经常更经济
Trap 2: 算 compute 忘 egress (跨 region egress 经常 = 30-50% of bill, 尤其大 LLM 流量)
Trap 3: 忘 monitoring + on-call FTE cost (24/7 on-call 至少 2 FTE rotation, $40K/月)
Trap 4: SLA composition — 你 service SLA 不能高于 dependency SLA. 你 99.99 但 RDS 99.95, 你最多 99.95
Trap 5: Deploy / planned maintenance 不算 in SLA 通常, 但客户会问. 提前说 "scheduled maintenance excluded from 99.99 calc"

🎯 面试现场 checklist (每题主动跑一遍)

  1. 听 problem statement → 找 trigger word (P1-P5)
  2. 问对应的 3 个澄清问题
  3. 算一遍 (用 calculator 或心算 anchor 数字)
  4. 说出数字 + 你的 assumption + cost / latency / storage
  5. 主动提省钱 knob (cache / batch / Flash / discount)
  6. 讲 break-even 或临界点 ("under 100M tok/月 hosted, over self-host")
  7. 提 trap (避坑信号: "but watch out for egress / output token / capacity buffer")

⭐ FDE senior 和 junior 的差别就在 trap 那一条 — 能主动说出 "watch out" 的人是已经踩过坑的, 招他不用培训.
