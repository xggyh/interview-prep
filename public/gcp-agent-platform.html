🏆 5 条黄金法则 (面试当下脑里跑)

  1. 说 2026 product name, 不说 "Vertex AI" — 大伞已经改名 Gemini Enterprise Agent Platform. 具体说 ADK + Agent Runtime + RAG Engine + Agent Studio, 不要笼统说 "Vertex".
  2. 每个能力都点名一个具体 sub-product — "agent 框架用 ADK, deploy 用 Agent Runtime, RAG 用 RAG Engine, eval 用 Gen AI Evaluation Service, safety 用 Model Armor". 越具体越内行.
  3. 跨 agent 必提 A2A protocol — Agent2Agent (Google 主推 2025 开源协议) 是 2026 multi-agent 标配. 不要再说 "agent 之间 HTTP 调".
  4. Workforce Identity Federation 接 Okta/SAML — 面到 enterprise SSO, 别说 "SSO with SAML"; 说 "Workforce Identity Federation, 不在 GCP 建 user, 直接 trust 客户 IdP".
  5. 承认 "Vertex AI" 还是 underlying — Agent Platform 是 Vertex AI 之上的 narrative layer; 底下 model serving / vector / training 仍走 Vertex. 不要不懂装懂说 Vertex 没了, 那是错的.

🏗️ Gemini Enterprise Agent Platform — the umbrella

2025 末 Google 把 "Agent Builder" + "Vertex Agents" + 一堆零散 SKU 合并 rebrand 成 Gemini Enterprise Agent Platform. 它不是一个新产品, 是一个 narrative + billing 伞. 底下分这几个真东西:

🛠️ Section 1 — Building agents (ADK + Agent Runtime + Studio)

ADK — Agent Development Kit2026 GA
What: Python (also Java/Go) SDK / framework for authoring agents — tool wiring, multi-step loops, memory, evaluation hooks, streaming. 开源 (Apache 2.0). 类比 LangGraph + AutoGen, 但 GCP-native.
When to use: 写自定义 agent 逻辑、需要代码级控制、要 multi-agent orchestration. 复杂 workflow 默认它.
from google.adk import Agent, Runner, Tool

@Tool
def lookup_order(order_id: str) -> dict:
    return bigquery.query(f"SELECT * FROM orders WHERE id='{order_id}'")

support_agent = Agent(
    name="support",
    model="gemini-3-pro",
    instructions="You help users with order issues.",
    tools=[lookup_order, escalate_to_human],
)

# Local run
result = Runner(agent=support_agent).run("Where is order #1234?")
FDE talking point: "I'd build the agent in ADK because it's open-source, framework-portable, and integrates natively with Gemini 3, Vector Search, and Memory Bank — no glue code."
Agent Runtime2026
What: Managed serverless host for ADK agents. 部署一次得 HTTPS endpoint + auto-scale + session state + observability. 类比 AWS Bedrock Agents runtime / Lambda for agents.
When to use: production deploy. 别自己起 GKE 跑 agent. Runtime 自动接 Cloud Logging / Trace / Audit.
# Deploy
$ gcloud agents deploy support \
    --source ./agent_dir \
    --runtime python312 \
    --region us-central1 \
    --service-account agent-sa@proj.iam \
    --vpc-connector projects/proj/locations/.../connectors/c1

# Invoke
$ gcloud agents invoke support --message "where is order 1234"
FDE talking point: "Deploy to Agent Runtime not Cloud Run — Runtime gives me session memory, tool tracing, and Model Armor hookup for free. Cloud Run is fine for stateless API, not agents."
Agent Studiolow-code UI
What: Web UI inside Google Cloud console — drag tool / drag knowledge source / drag guardrail, output 一个 Runtime-deployable agent. 给 PM / BA / 非 dev 用.
When to use: customer 想自己 own agent 迭代但没 ML team; demo / POC 阶段; FAQ-style assistant 不需要复杂逻辑.
FDE talking point: "I'd give the customer's business team Agent Studio for prompt iteration, while my team owns the ADK tools layer. Two-speed ownership keeps engineering bottleneck off the BA team."
常被搞混: "Dialogflow CX" 还活着吗? 答: 还活着, 但只推荐做窄场景 IVR / FAQ. 新 agent 一律默认 ADK + Runtime. 面试不要主推 Dialogflow.

📚 Section 2 — RAG & memory (RAG Engine + Vector Search + Memory Bank)

RAG Engine2026 GA
What: Managed end-to-end RAG pipeline. 你给文档 (GCS / Drive / SharePoint), 它做: parse → chunk → embed → store → retrieve → rerank. 一个 API create_corpus + query 搞定. 类比 AWS Bedrock Knowledge Bases.
When to use: 95% RAG 场景默认它. 不要手撸 embed + Vector Search + rerank 三步 — 客户 maintain 不动.
from google.cloud import rag

corpus = rag.create_corpus(
    name="support-kb",
    embedding_model="text-embedding-005",
    chunk_size=512,
    rerank_model="semantic-ranker-default",
)
rag.import_files(corpus, paths=["gs://kb/*.pdf", "drive://folder/abc"])

# Query
results = rag.query(corpus, "what is refund policy", top_k=8)
# returns: chunks + citations + scores

# Wire into ADK
agent = Agent(model="gemini-3-pro", tools=[rag.as_tool(corpus)])
FDE talking point: "Default to RAG Engine, not hand-rolled. Customer ops team can refresh the corpus by dragging PDFs to a GCS bucket; no ML engineer needed for content updates."
Vector Searchrenamed from Matching Engine
What: 独立 managed ANN service (HNSW + IVF). 千万-十亿 vectors. 仍叫 Vector Search (不再叫 "Vertex AI Vector Search", 简化 brand).
When to use: 当 RAG Engine 太黑盒 — 需要 custom 切片 / 多 namespace / 自己 rerank / hybrid retrieval. 或者非 RAG 用途 (recommender, image dedupe).
FDE talking point: "RAG Engine default; if the customer needs hybrid BM25 + dense or custom rerankers, drop to raw Vector Search + Vertex Embeddings."
Memory Bank2026
What: Long-term agent memory. 不是 session state, 是 per-user / per-tenant persistent fact store. Auto-extracts facts from conversation, stores with embeddings, retrieves on next turn.
When to use: 用户回访的 assistant (customer support / personal assistant). 短 session 不需要.
agent = Agent(
    model="gemini-3-pro",
    memory=MemoryBank(
        scope="user_id",        # per-user partition
        retention_days=365,
        pii_filter="model_armor",
    ),
)
FDE talking point: "Memory Bank handles 'remember I'm vegetarian' across sessions — agent doesn't re-ask. PII goes through Model Armor before write."

🔗 Section 3 — Inter-agent communication (Agent2Agent / A2A)

Agent2Agent (A2A) ProtocolGoogle open spec 2025
What: 开源协议 (Google 主导, 50+ partners signed). HTTP/JSON-RPC + SSE for streaming. 让一个 agent 调另一个 agent — 不管是不是同一个 cloud / 同一个 framework. 跟 MCP 互补: MCP = agent ↔ tools/data, A2A = agent ↔ agent.
When to use: multi-agent 系统; 跨组织 agent 协作 (买方 agent 跟卖方 agent 谈判); 需要 standard discovery + auth.
# Agent A (orchestrator) discovers Agent B via agent card
GET https://b.example.com/.well-known/agent.json
→ { "name": "shipping-agent", "skills": ["track", "rebook"], ... }

# Send task
POST https://b.example.com/a2a/tasks
{ "method": "tasks/send",
  "params": { "id": "task-1", "message": "track FedEx 12345",
              "auth": { "scheme": "bearer", "token": "..." } } }

# Stream updates via SSE
GET /a2a/tasks/task-1/stream → event: status / artifact / done
MCP vs A2A 一句话: "MCP = how an agent talks down to tools and data. A2A = how an agent talks sideways to peer agents. I use both: MCP gateway for 500 internal APIs, A2A for the 3-agent orchestrator topology."
FDE talking point: "For the multi-agent design I'd use A2A rather than raw HTTP — standard agent cards for discovery, native streaming, and partners outside GCP can join without bespoke integration."

🛡️ Section 4 — Safety & evaluation

Model ArmorGA
What: Managed safety layer — prompt-injection detection, PII redaction, jailbreak filtering, malicious URL block, sensitive content classification. 直接挂在 agent 入/出方向, 不用客户写 regex.
When to use: 任何 prod agent 都该有. 类比 AWS Bedrock Guardrails / OpenAI Moderation, 但 GCP-native + BAA-covered.
from google.cloud import modelarmor

template = modelarmor.create_template(
    name="support-guard",
    filters={
        "pii": "redact",              # SSN / 信用卡 etc.
        "prompt_injection": "block",
        "jailbreak": "block",
        "malicious_uri": "block",
        "rai_dangerous": "block",     # CSAM / self-harm / etc.
    },
)

# Wire into ADK
agent = Agent(
    model="gemini-3-pro",
    armor_template="support-guard",   # in + out both filtered
)
FDE talking point: "Model Armor is the safety frontline — it catches prompt injection before the model sees the input, and PII before the response leaves. I'd never ship an agent without it; that's the 2026 minimum bar."
Gen AI Evaluation Serviceaka Model Eval
What: Managed eval — 上传 dataset (input / expected) → run model or agent → get pointwise (factuality, fluency, safety) and pairwise (A vs B) scores. Supports LLM-as-judge with Gemini, and rubric-based custom metrics.
When to use: 模型/prompt 迭代; A/B test ADK agents; regression eval pre-deploy gate.
from vertexai.evaluation import EvalTask

task = EvalTask(
    dataset="gs://eval/support-qa.jsonl",
    metrics=["groundedness", "instruction_following", "safety",
             "tool_use_quality"],
    experiment="support-agent-v3",
)
result = task.evaluate(model=my_agent)
# → table of scores, regression vs v2 baseline
FDE talking point: "I gate deploys on Gen AI Evaluation Service — every PR runs the eval set; if groundedness drops >3pp vs main, the deploy blocks. Same pattern as unit tests but for LLM behavior."

🎯 Section 6 — Composition example: "Customer support agent" end-to-end

场景: 7 国 e-commerce 的 customer support agent. Multilingual, retrieves policy + order data, can refund, escalates to human, all PII-safe, SOC2-audit-ready.
[Customer chat in Web / app / WhatsApp] │ ▼ ┌─────────────────────────────────────────┐ │ Apigee API Gateway (rate limit, auth) │ └─────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ Model Armor (in: jailbreak / PII) │ ← step 1: filter input └─────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ Agent Runtime → ADK agent (Gemini 3) │ ← step 2: route │ Memory Bank (per-customer history) │ │ Tools: │ │ • lookup_order → Cloud SQL │ │ • refund → internal API/MCP │ │ • escalate → A2A to human- │ │ handoff agent │ │ • policy_search → RAG Engine corpus │ └─────────────────────────────────────────┘ │ ▼ ┌─────────────────────────────────────────┐ │ Model Armor (out: PII redact, safety) │ ← step 3: filter output └─────────────────────────────────────────┘ │ ▼ [Response] Cross-cutting: ├ VPC Service Controls around all GCP services ├ Workforce IdP Fed for staff (Okta) ├ Cloud Audit Logs every tool invocation logged ├ Gen AI Eval Service nightly regression on 500 cases └ Cloud Monitoring latency p95, tool error %, armor block %

口播版 (90 秒讲完上图)

"客户消息进来先过 Apigee 做 rate-limit 和 auth, 然后 Model Armor 在入方向挡 prompt injection 和 PII. 干净的 input 进 Agent Runtime 上的 ADK agent — model 用 Gemini 3 Pro 2M context. Agent 有 4 个 tool: lookup_order 走 Cloud SQL, refund 走内部 API (通过 MCP gateway), policy_search 走 RAG Engine, escalate 通过 A2A 调 handoff agent. Per-customer 记忆用 Memory Bank. Response 出来再过一次 Model Armor 做 PII redaction. 整个 perimeter 用 VPC Service Controls 锁死, 员工 SSO 走 Workforce Identity Federation 接 Okta, 所有 tool 调用进 Cloud Audit Logs, 每晚 Gen AI Evaluation Service 跑 500 case regression."
Resume hook 映射: Gao Xin 在 TikTok 做的 PayLater 7-market voice agent (2024) 对应到 2026 stack 就是 ADK + Agent Runtime + RAG Engine (policy KB) + A2A (escalation to human) + Model Armor (PII for SSN-like IDs) + Memory Bank (复访客户) + Workforce IdP Fed (CSM SSO). 面试时直接把旧 project 用 2026 词汇重述一遍, 立刻显得 current.

🎤 Section 8 — Interview talking scripts (3 口播)

Script A — "How would you build this agent on Google Cloud?" (30 秒)

SHORT · name-drop 4 products in 1 breath
"I'd build it on the Gemini Enterprise Agent Platform. The agent itself is an ADK Python module — Gemini 3 Pro as the planner, tools wired through MCP. Deploy to Agent Runtime for managed scaling and session state. Knowledge comes from RAG Engine over the customer's GCS corpus. Model Armor sits in front for prompt-injection and PII. Audit goes to Cloud Audit Logs, and the whole thing lives inside VPC Service Controls. That's the 2026 default stack."

Script B — "What's new in 2026 GCP Agent stack?" (45 秒)

MEDIUM · show you tracked the rename + new SKUs
"Three things shifted in the last 12 months. One, Google consolidated Agent Builder + Vertex Agents into Gemini Enterprise Agent Platform — the sub-products you actually use are ADK (the SDK), Agent Runtime (the managed deploy), and Agent Studio (low-code). Two, RAG Engine went GA so you don't hand-roll embed+search+rerank anymore — it's a one-API managed pipeline. Three, the Agent2Agent / A2A protocol that Google open-sourced is now the multi-agent standard; pairs with MCP, where MCP is agent-to-tool and A2A is agent-to-agent. Plus Model Armor for safety, Gen AI Evaluation Service for managed eval, and Memory Bank for long-term per-user memory."

Script C — "Why use Agent Platform vs build it yourself?" (60 秒)

LONG · push back on the false dichotomy
"Two reasons. One — time-to-value. If I hand-roll, I'm writing chunking, embedding, ANN, rerank, prompt-injection filter, eval harness, audit pipeline. That's 4-6 engineer-months before the first useful demo. With RAG Engine + Agent Runtime + Model Armor, that's about a week. Two — compliance & ownership. Agent Runtime runs inside the customer's GCP project; the data never leaves their VPC and is BAA-covered. If I custom-build, I have to argue compliance from scratch — auditors hate that. The honest tradeoff: managed services give up some flexibility — e.g., RAG Engine's reranker isn't swappable. So for the 10% where I need custom chunking or hybrid retrieval, I drop one layer down to Vector Search + Vertex Embeddings directly while keeping Runtime + Armor + Audit. Best of both."
面试 tip: 这 3 个 script 哪个抽到都能用. 关键是中间能流畅说出 4-6 个 2026 sub-product 名 — 这是 "currency" 信号. 模糊说 "I'd use Vertex AI" 表示你停在 2023 认知.
