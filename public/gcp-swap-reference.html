🏆 5 条黄金法则 (面试当下脑里跑)

  1. 默认 GCP-first — 听到题目立刻在脑里把 stack 摆成 GCP, 不是 AWS 翻译版.
  2. 主动提 Google 独有优势 — Gemini 3 Pro 2M context / Vertex AI in customer project / Workspace 入口 / TPU. 别人没有的, 别只比相同的.
  3. BAA 自动覆盖 — 面试官提到 HIPAA / GDPR / FedRAMP, 一定说 "Vertex AI / BigQuery / GCS / Document AI / Healthcare API 都在 Google BAA list 默认覆盖". 这是 GCP vs OpenAI 直接 API 的最大差异化.
  4. 用 GCP 自家术语 — VPC Service Controls / CMEK / Cloud Audit Logs / Private Service Connect. 这些一说就是内行.
  5. 承认 AWS 等也行 — 但要补一句 "but for this Google FDE engagement I'd default to GCP-native stack" 显示你不是 AWS-only 一根筋.

🎤 面试话术 — 3 个口播版本

① 设计题被问 "你会怎么 deploy"

"Default to GCP-native stack since this is a Google FDE engagement. The agent runs on Vertex AI in customer's GCP project, data sits in BigQuery with CMEK, retrieval through Vertex AI Vector Search, and Workspace surfaces if user-facing. Customer audit goes to Cloud Audit Logs. The whole perimeter is locked with VPC Service Controls."

② 被问 "为什么 GCP 不 AWS"

"Three things AWS can't match for this use case: (1) Gemini 3 Pro's 2M context — Claude on Bedrock is 200K, Llama is 128K. (2) Vertex AI in customer's own project with BAA covered, vs Bedrock which is multi-tenant managed. (3) Workspace as the last-mile distribution — no AWS equivalent for Gmail / Docs / Drive integration. Then there's TPU for cost-sensitive training. But I'm not religious — for non-GenAI workloads, AWS / Azure are all valid."

③ 客户已经在 AWS, 怎么 propose 用 GCP

"I wouldn't ask the customer to fully migrate — that's a deal-killer. I'd propose a hybrid pattern: keep their compute on AWS, but the AI workload (Vertex AI + Gemini) runs on GCP, connected via Cloud Interconnect or peering. Data flows: AWS RDS → BigQuery (federated query, no copy) → Vertex AI. They keep their existing investment, get Gemini's capability. This is the standard 'best-of-breed' enterprise pattern in 2026."
