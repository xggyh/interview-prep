Problem Statement

🔮 Google FDE 预测题. 经典 FDE 客户迁移. Per-app golden dataset + A/B eval + LLM-as-judge + LiteLLM abstraction + 厂商谈判. 即使 0 迁移也省 $400K. ~870 行 deep-dive.

我的思路与解法

Q-P4 · F500 客户从 OpenAI 迁移到 Gemini 3 Pro

"A Fortune 500 customer is currently running 12 production applications on OpenAI GPT-5 (~$2M / year LLM spend). Their contract is up for renewal. The CTO is exploring Gemini 3 Pro as an alternative — it's 30% cheaper in input/output, has 2M context vs OpenAI's 400K, and they're already on Google Cloud. But the team is nervous about quality regression on their specific workloads (legal contract review, customer support, internal search). You're the FDE assigned to lead the evaluation + potential migration in Q3 (3 months). Walk through your plan."

中文翻译:

"一家 F500 客户现在在 OpenAI GPT-5 上跑了 12 个生产应用 (LLM 一年花约 $2M). 他们的合同快续了. CTO 在考虑把这些迁移到 Gemini 3 Pro — 比 OpenAI 便宜 30%, 上下文 2M (OpenAI 才 400K), 而且他们本来就在 Google Cloud 上. 但团队担心 质量回退 (quality regression) — 特别是在他们的具体场景里 (legal 合同审查 / 客户支持 / 内部搜索). 你作为 FDE, 要在 Q3 (3 个月) 内负责这次评估 + 可能的迁移. 跟我讲讲你怎么做."

📖 术语速查 (本题用到的)

这题里的迁移 / eval / 商务词如果不懂, 听都听不下去. 这张表 5 min 看完, 后面就跟得上.

业务 / 商务

术语解释
F500 (Fortune 500)美国营收前 500 大公司. 通常意味着 multi-cloud / multi-vendor / 复杂采购流程 / legal review 6+ 周 / Procurement 团队是 vetoer.
CTO sponsor项目出资 + 政治支持人. 一旦 CTO 拍板, 团队反对没用. 但 CTO 也会"换风向"(政治压力下放弃迁移).
TCO (Total Cost of Ownership) ⭐总拥有成本 = LLM API token cost + 工程迁移成本 + 风险成本 + opportunity cost (机会成本). 不是单纯 API price 比价.
Contract renewal合同到期续约. 这是 最强 leverage 时刻 — 即使最终不迁移, 用 Gemini quote 也能从 OpenAI 砍价 20-30%.
Committed-use discount (CUD)承诺消费折扣. 一年 $1M 承诺消费, OpenAI/Google 给 20-30% discount. 这题 $2M/year = 大客户.
Volume tier pricing量阶折扣. > $500K/year 一档, > $2M/year 一档. F500 通常在最高档.
Support tier厂商支持等级. Enterprise = 24/7 + 专属 TAM + SLA. 比 token price 还重要 — bug 找不到人 = 项目卡死.
TAM (Technical Account Manager)厂商分配的技术客户经理. 不是 sales, 是 customer-facing 工程师. 好 TAM 可以加速 6 周, 烂 TAM 拖 6 个月.
Vendor lock-in厂商绑定. 用 OpenAI 专属 feature (function calling format / Assistants API / batch) 越深, 迁移成本越高.
Multi-vendor / multi-model strategy多厂商策略. 不押单一供应商, 用 abstraction layer (e.g. LiteLLM) 同时跑 GPT + Gemini + Claude.

Eval 方法论 ⭐ 这题的关键

术语解释
Golden dataset ⭐黄金评估集. 100-1000 个人工标注的高质量 (query, ideal_answer) 对. 每个 application 必须有自己的 golden set — generic benchmark 不算.
Per-app evaluation ⭐按应用单独 eval. 这题 12 个 app 不是 1 个模型适配 12 个场景, 是 12 套独立 eval + 独立决策. 这是核心 framing.
Pairwise comparison ⭐成对比较. 同一 query 喂给 GPT-5 和 Gemini 3 Pro, 拿到两个 response, 判断哪个更好. 比单独打分准.
LLM-as-judge ⭐用 LLM (e.g. Claude Opus 4.7) 当评委. 比人工快 100×, 但要 disagreement rate 控制 + 人工抽样 (5-10% 人工 review 验证 judge 的偏见).
Win rate在 pairwise 比较里, 模型 A 胜过 B 的比例. > 55% 算显著优, 45-55% 算 tie, < 45% 算显著劣.
Tie rate平局比例. 如果 tie rate > 40%, 说明用例对 model 区分度低 — 可能两个都行, 选便宜的.
Regression test ⭐回归测试. 现有 GPT-5 答案是 baseline, Gemini 3 Pro 答案对比. 任何 quality drop > X% 触发 alarm.
Shadow mode (影子模式) ⭐新模型并行接收线上 query, 但回答 不返回用户, 只 log. 用真实流量评估新模型, 0 用户感知风险.
Stratified eval分层评估. 按 app 类型 / 客户细分 / query 难度分桶, 每桶单独算 win rate. 避免"平均分掩盖具体场景滑铁卢".
Disagreement review ⭐模型分歧人工 review. GPT 和 Gemini 答案差异大的样本 (~5%) 重点人工看, 找出系统性差异.
Benchmark contamination评估集泄漏. 公开 benchmark 数据可能在 model 训练集里. Golden set 必须 自建 + 私有.
MMLU / GPQA / SWE-bench公开 benchmark. 不能作为 production decision 的依据 — 太通用.

厂商 / 模型 (2026 现状)

术语解释
GPT-5OpenAI 2026 旗舰模型. 400K 上下文. $5/$30 per 1M tokens (in/out).
GPT-5.5OpenAI 2026 中期升级. Function calling 改善, structured output JSON mode 强化. $5/$30 同价.
Gemini 3 Pro ⭐Google 2026 旗舰. 2M context (全行业最大), $2/$12 per 1M tokens, native multimodal, grounding via Google Search 原生支持.
Gemini 3 FlashGoogle 中端模型. $0.50/$3 per 1M tokens. 用于 high-volume / latency-sensitive / 简单 routing 场景.
Vertex AI ⭐Google Cloud 上的 model serving 平台. 提供 Gemini API + 第三方 (Claude / Llama) 托管. Enterprise BAA, VPC-SC, CMEK.
Claude Opus 4.7Anthropic 2026 旗舰. $15/$75. 复杂推理强但贵, 大客户也常作为 3rd 备选.
Function callingLLM 调用工具的 schema. OpenAI 和 Google 的 schema 不完全兼容 (parameter format 差异).
Structured output / JSON mode强制 JSON 输出. OpenAI 通过 response_format, Google 通过 response_schema. 不兼容.
Grounding让模型回答基于外部 source (e.g. Google Search / 客户文档) 而非记忆. 减少幻觉. Gemini 原生支持 Google Search grounding.

Abstraction layer / 工程

术语解释
LiteLLM ⭐开源 LLM 路由层 (BerriAI/LiteLLM). 统一 OpenAI 格式 API, 后端可路由到 OpenAI / Gemini / Claude / Bedrock / 100+ models. 不是迁移工具, 是长期 abstraction.
OpenRouter商业 LLM 路由 SaaS. 类似 LiteLLM 但托管. 适合不想 self-host gateway 的客户.
Abstraction layer抽象层. 应用代码不直接调 OpenAI SDK, 而是调内部 gateway, 由 gateway 决定走哪个模型. 一次写, 多 vendor 跑.
Kill switch ⭐一键回滚. 新模型出问题, 30s 内全流量切回 OpenAI. 这是 enterprise migration 的标配, 没 kill switch 没人敢上.
Prompt portability ⭐Prompt 跨模型可移植性. 一个 GPT-5 的 prompt 直接喂 Gemini 3 Pro 大概率效果差 — system prompt format 不同, few-shot 例子需要重选, 输出格式约束句子要重写.
Prompt drift同 prompt 在不同模型上的输出差异. 跨模型时所有 prompt 都需要 重新调 (prompt re-engineering).
Cost telemetry / per-app billing按应用统计 token 消耗 + 成本. Migration 后要能 attribute 每个 app 实际省了多少 — 否则 CFO 问 "省了多少" 答不出.
Cascade / model routing模型级联. Cheap model (Flash) 先答, confidence 低 fallback 到 expensive model (Pro). 进一步降本.
Caching layer缓存层. 相同 prompt + same context 直接返回 cached response. 命中率 20-40% 时省钱 + 加速.

风险 / 失败模式

术语解释
Quality regression ⭐质量回退. 迁移后某个 app 答案变差. 这是工程团队最怕的事.
Latency regression延迟回退. Gemini 在大上下文上 p99 可能比 GPT 慢 — chatbot 场景敏感.
Hallucination delta幻觉率差异. Legal 合同审查场景, 幻觉 +1pp 都不能接受.
Edge case failure长尾失败. Eval set 100-1000 个 sample 看不全, prod 流量上跑才暴露.
Vendor model drift ⭐厂商悄悄改模型. OpenAI / Google 都偶尔在不改版本号情况下 fine-tune model — 测试时通过, 一个月后退化. 防御: 持续 monitoring + 季度 re-eval.
Procurement veto采购否决. 即使 CTO 拍板, Procurement (法务 / 供应商管理) 可能因 contract clause 拒绝.
Data residency数据驻留. F500 可能要求数据存某特定 region (EU GDPR / 美国本土). Vertex AI 和 OpenAI 的 region coverage 不同.
BAA / DPABusiness Associate Agreement (HIPAA) / Data Processing Agreement (GDPR). 不同厂商法务条款不同, F500 法务通常要 6 周 review.

这道题在考什么

不是: 考你能不能 setup Vertex AI 和写迁移代码.

是: 考你能不能在 12 个不同 app + 3 个月 deadline + 工程团队不安 + 商务谈判 leverage 真实约束下做 结构化迁移 + 不迁也算赢 的双轨思维.

5 个 signal:

  1. Don't migrate everything (别说全迁) — 答案大概率是 8 个迁 / 2 个留 / 2 个 hybrid. 一刀切迁=政治灾难 + 质量回退. 真正的 FDE 答案是 per-app decision.
  1. Eval methodology > migration code (评估方法论比迁移代码重要) — 没 eval, 迁移就是赌博. Golden dataset + pairwise + LLM-as-judge + 人工 review 是核心 IP, 写代码是 6 周工作.
  1. Even partial migration = leverage (哪怕部分迁移也是商务筹码) — Gemini 报价拿到手 → OpenAI 砍价 20-30% → 客户即使一个 app 都不迁, 一年省 $400K. "不迁也算赢" 是 FDE 的 second-order thinking.
  1. Abstraction layer matters more than this migration (抽象层比这次迁移本身更重要) — 这次迁完, 下次 Claude 4.8 出来还要再迁吗? 建一次性的 abstraction 一次, 之后 multi-vendor 永久受益. LiteLLM 是答案.
  1. Manage CTO + engineering team political tension (管 CTO 和工程团队的政治张力) — CTO 想省钱迁, 工程团队怕回退抵抗. FDE 必须 let evidence decide, not opinion. 通过 eval 数据让两边都不能拍脑袋.

❌ 最常见的挂法

挂法 #1: 立刻冲 "I'd swap OpenAI SDK calls with Vertex AI SDK calls" (立刻冲去讲怎么换 API)

"I'd write a migration script that replaces openai.chat.completions.create with vertex_ai.GenerativeModel, run it through their 12 apps, and we'd be done in 6 weeks."

死. 你没问:

  • 12 个 app 都是什么场景? (Legal 合同 vs 客服 vs 内部搜索 — eval 完全不同标准)
  • 每个 app 当前 P0 metric 是什么? (Accuracy / latency / cost / customer satisfaction?)
  • 已有 eval pipeline 吗? Golden dataset 在哪?
  • 工程团队是哪几个? 他们的 concern 是什么? (技术问题 vs 政治问题)
  • Function calling 用得深吗? Structured output 用得深吗? (Vendor lock-in 越深迁移越贵)
  • 客户在 GCP 上, 但 OpenAI 调用走哪? (Azure OpenAI? OpenAI direct? Each has different egress cost)

挂法 #2: "全迁 Gemini 省 30%" (一刀切迁全部)

"Since Gemini is 30% cheaper, we'd save $600K/year. Migrate everything in Q3."

死. 12 个 app 里:

  • Legal 合同审查 (high stakes, accuracy critical) — Gemini 在某些 legal 场景可能不如 GPT-5
  • 客服 (high volume, latency critical) — Gemini Flash 可能更适合, Gemini Pro 反而过 spec
  • 内部搜索 (RAG, 上下文长) — Gemini 2M context 优势爆炸, 应该迁
  • 12 个 app 大概率是 8 个迁 + 2 个留 + 2 个混合用. 一刀切的人 fail FDE 面试.

挂法 #3: 忽略商务谈判 leverage (只讲技术不讲商务)

"I'll lead the technical migration, the contract is separate."

死. FDE 的 second-order play 是: 拿 Gemini 评估结果回去和 OpenAI 谈判. 即使最后 0 个 app 迁移, "我们做了认真 Gemini eval, OpenAI 看到威胁就降价" = 客户省 $400K-$600K/year. 这是 FDE 给客户的 hidden value.

挂法 #4: 接受 3 个月 deadline 闷头做

"3 months is enough for 12 apps if we parallelize."

死. 12 个 app 各有自己的 golden dataset 要建 (每个 100-1000 例 × 人工标注 = 2-4 周/app), 加上 prompt re-engineering, eval, shadow mode, 真正能在 3 个月落地的是 4-6 个 app, 而且只能上 2-3 个低风险的. 必须 reverse scope.

挂法 #5: 不建 abstraction layer, 直接换 SDK

"Just pip install google-genai and replace imports."

死. 现在不建 LiteLLM 之类的 abstraction, 6 个月后 Claude 4.8 出来又要再做一次, 18 个月后 GPT-6 出来再做一次. 一次工程, 多次受益. 这是 staff-level 思维.

核心理念: 5 个 clarifying 维度 1:1 映射到 5 个 decompose 步骤. 问完一轮 G·O·D·D·S, decompose 也就基本写好了.

"12 apps is NOT one migration project — it's 12 independent evaluations with potentially 4 different outcomes."

G — Goal (→ feeds Decompose Step 1: KPI lock)

Q1: "When the CTO says 'explore Gemini', what's the success metric for him? Is it (a) save $X on LLM spend (a financial number), (b) demonstrate multi-vendor capability (avoid OpenAI lock-in), (c) unblock features requiring 2M context (long-context use cases stuck on 400K), (d) respond to a board mandate (CEO wants Google partnership story), or (e) all of the above? Each scenario changes scope dramatically."

Q2: "Out of 12 apps, are there clear winners I should prioritize (e.g. internal search where 2M context = obvious huge win), or is the CTO expecting a portfolio-wide migration regardless of app fit?"

这层 → 解锁 Decompose Step 1: 答完 G 问题, 你就知道这道题的 KPI 是什么 (e.g., $400-600K/year save + 2 apps unblocked on long-context + Gemini partial commit signed by Q3), 后面 5 步的所有决策按这个 KPI 优化 — 也决定 "migrate all 12" 还是 "evaluate all + migrate Pareto winners".

O — Owner (→ feeds Decompose Step 2: Stakeholder map)

Q3: "Who's the engineering counterpart I'd work with? Is it one platform team that owns LLM infra across 12 apps, or are 12 apps owned by 12 different teams each with their own concerns? If the latter, my plan changes — need 12 partnerships, not 1."

Q4: "Veto power + sentiment: who can kill this migration? Procurement (OpenAI contract clauses)? Legal (Google DPA review)? Security (new vendor data handling)? CISO (model data residency)? Any of the 12 app owners? And: when you say 'team is nervous', is it technical (Gemini quality fears), operational (no Vertex experience), or political (CTO pushing w/o eng input)?"

这层 → 解锁 Step 2: 答完 O 问题, 你画出 stakeholder map (sponsor = CTO / counterpart = AI Platform tech lead / blocker = Procurement + Security + legal-app skeptic / SME = each app owner) — 知道 12-apps × 3-personas matrix 怎么 align, 哪几个 app owner 需要被特别 win-over.

D — Data (→ feeds Step 3: 数据 inventory)

Q5: "What eval assets exist already? Per-app golden datasets? Production query logs? Customer feedback labels? Without baseline eval data, the first 4 weeks is building eval infrastructure, not evaluating. Do any apps have human-graded gold sets > 100 samples?"

Q6: "Per-app token / cost / compliance breakdown: of the $2M/year spend, what's the distribution across 12 apps? Pareto suggests 2-3 apps probably consume 60-80%. And: any apps subject to HIPAA / GDPR / SOC2 that constrain region/vendor choice? Vertex and OpenAI have different region + BAA coverage."

这层 → 解锁 Step 3: 答完 D 问题, 你能画 12-app inventory 表 (app × token volume × $/month × eval gold set size × compliance class × rollback difficulty × current Assistants-API depth) — 用这张表直接做 prioritization matrix.

D — Deadline (→ feeds Step 4: 子问题排序)

Q7: "Why Q3 (3 months) specifically? Is it driven by (a) OpenAI contract expiry date (hard deadline), (b) board demo / earnings call (soft but political), (c) Google fiscal year / CUD commit signing deadline, (d) engineering capacity window, or (e) arbitrary CTO target? Driver determines what's compromisable."

Q8: "Worst-case appetite + rollback: if we migrate app X and customer satisfaction drops 5pp, can we roll back in 30 minutes (abstraction layer ready) or are we stuck for a quarter (deep API integration like legal app on Assistants API)? Reversibility per app changes risk tolerance and migration order."

这层 → 解锁 Step 4: 答完 Deadline 问题, 你知道为什么 Q3 这个数 (e.g., Aug 31 OpenAI renewal — but soft, can extend 90 days), 才能 push back. 12 apps 按 (deadline-pressure × $-savings × rollback-ease × eval-readiness) 排序: 内部搜索 + 客服 (Pareto + reversible) 排最前, legal Assistants-API app 排最后 (high lock-in).

S — Scope cut (→ feeds Step 5: Walking-skeleton MVP)

Q9: "In 3 months, would you accept: (a) eval-complete + 0 apps migrated (data-driven decision, no risk), (b) 2-3 lowest-risk Pareto apps fully migrated + Gemini commit signed for procurement leverage, or (c) all 12 partially migrated (any failures = embarrassing demo)? My instinct: (a) for first 6 weeks → (b) for last 6 weeks — finish eval first, ship the safest wins, leave hard apps (legal Assistants API) for Q4."

Q10: "Which apps are explicitly out of Q3 scope — (a) any HIPAA app (BAA setup is 4-6 weeks alone), (b) any app < $50K/year spend (not worth the eng), (c) the legal app on Assistants API (deep rewrite needed), (d) any app < 100 sample gold set (eval not trustworthy)? My recommendation: MVP = 4-6 apps: top-spend × eval-ready × reversible × no-compliance-blocker; everything else gets a 'recommendation report' but no migration."

这层 → 解锁 Step 5: 答完 S 问题, MVP 边界明确. 你知道哪 80% 砍掉先不做 (HIPAA apps, low-spend apps, deep-lock-in Assistants-API apps, no-gold-set apps, EU-residency-blocked apps), 哪 20% 是 walking skeleton (eval harness up in week 1 + 4-6 Pareto apps migrated with vendor abstraction layer + Gemini partial CUD as procurement leverage + Q4 plan for the rest).

面试官 likely 回答:

  • (a) Save $400-600K/year + (c) unblock 2M context features for internal search
  • 8 of 12 apps owned by central AI Platform team, 4 owned by product teams

  4. "不需要 abstraction layer, 直接换 SDK" — 6 个月后下个模型出来又要再做一遍
  5. "接受 3 个月 deadline 迁 12 个" — 时间不够, 不 reverse scope
  6. "只做技术不参与商务" — 错过 $400K-$600K 的谈判 leverage
  7. "忽略工程团队 nervous, 用 CTO authority 强推" — 后续 oncall 时团队 sabotage
  8. "不做 shadow mode, 直接 canary" — 没有 production traffic 上的真实质量数据就上 canary 是赌博

✅ 加分项 (top 10)

  1. G·O·O·D-F·T 10 个问题 — 立刻 signal staff-level clarifying
  2. Reframe "12 apps = 12 decisions" — 反一刀切, 体现成熟判断
  3. Eval methodology 占 60% 工作量 — eval-first thinking
  4. Per-app stratified decision matrix — 不是平均分, 是切片
  5. Abstraction layer (LiteLLM) 作为长期资产 — 这次迁完, 下次更便宜
  6. Shadow → canary → full + kill switch — production safety culture
  7. "Even 0 migration = $400K save via negotiation" — second-order thinking, 客户也许没意识到
  8. Legal team trauma management (defer, not force) — 政治成熟度
  9. Quarterly re-eval + vendor drift defense — 不是 one-shot
  10. TikTok 简历 reframe (7 markets, Internal Agent Platform, BNPL cascade) — 直接 transfer experience

一句话总结

F500 OpenAI → Gemini 迁移 = "12 apps = 12 decisions, not 1 migration" + "eval methodology > migration code" + "abstraction layer 是长期资产" + "即使 0 迁移也能省 $400K 通过谈判 leverage" + "let evidence decide, not CTO opinion".

真正的 FDE win 不是迁 12 个 app, 是给客户搭一个 多厂商灵活架构 + 系统化 eval 能力 + 商务谈判杠杆, 之后 Claude 4.8 / GPT-6 出来都 1 周内切换. Per-app evidence-based 决策, 6 迁 / 2-3 hybrid / 2-3 留, 比 12 全迁 更专业更可信.
